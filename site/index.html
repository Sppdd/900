Give your coding agent a panel of sandboxed specialists.

Your agent asks. A security auditor, a test writer, a bug reproducer and a feature researcher each fork the same snapshot of your repo in an isolated Nebius sandbox, run real tools in parallel, and return evidence your agent can act on: proof-of-concept tests, passing test patches, failing regression tests. Your laptop never runs their code, and your secrets never leave it.

One snapshot, many specialists, evidence back

Token Factory Sandboxes save an immutable snapshot after every step. sandcoder builds the project once, then forks it for each specialist, so they run in parallel from exactly the same state and none of them can affect the others.

Parallel from one state

Setup runs once. Each specialist forks the same snapshot, so a 4-specialist panel costs 4 agent loops, not 4 environment builds.

Executed evidence

Each finding carries the command that proves it, and every result links to a snapshot you can re-run. They are tests and diffs, not opinions.

Cheap models do the grunt work

NVIDIA Nemotron on Token Factory runs the loops. Your main model only reads short, structured verdicts, which keeps its context clean.

The specialists

Each specialist is a folder of data: a SKILL.md with its role and method, and a skill.toml with its tools, budgets, toolchain and preflight probes. Add your own without writing code.

⛨

security-auditor

Runs bandit, semgrep and pip-audit, reviews what scanners miss, and tries to prove each serious issue with a failing proof-of-concept test.

returns: findings · PoC tests · fix patch
✓

test-writer

Measures coverage, writes tests for untested paths in your project's style, and keeps only tests that pass. Tests that expose a bug come back as findings instead.

returns: test patch · coverage delta
⟲

bug-reproducer

Turns a bug report into the smallest regression test that fails for the right reason. It doesn't fix anything; it pins the bug down.

returns: failing test · root cause
⌕

feature-researcher

A planner proposes 2–3 approaches (optionally with Tavily web search). Each one is implemented in its own parallel sandbox fork, and the harness picks the winner from measured facts: tests, diff size and risk.

returns: comparison · recommended patch

Built for untrusted code and prompt injection

Specialists read your code, README, issues and web pages, and any of those can contain instructions aimed at an AI. sandcoder assumes some of it will be hostile.

1

Isolation, the real boundary

Every specialist runs in a VM-isolated, disposable sandbox with no credentials. Model and web-search calls run in the MCP process, so API keys never enter a sandbox.

2

Secrets never uploaded

Uploads respect .gitignore and always drop .env, private keys, .npmrc, tfstate and other credential files.

3

Command guard

Every shell command is checked first. Exfiltration, curl | sh, env dumps, ~/.ssh reads, reverse shells, miners and unknown hosts are denied and logged.

4

Patch risk scanner

Every diff is rated before your agent sees it. Weakened tests, CI edits, new dependencies, network calls, eval and encoded blobs are flagged with reasons.

5

Results are data

Verdicts are schema-validated and length-capped. The plugin skill tells your agent never to follow instructions inside results and never to apply a patch without showing you the diff.

6

Versioned skills

Each skill is identified by a content hash reported with every result, so you always know exactly which instructions ran.

Honest scope: layers 3 and 4 catch common attacks, not a determined adversary. Isolation, and you reviewing the diff, are what keep you safe.

Install

You need a Nebius Token Factory API key and a project id with Sandboxes enabled, plus uv. The software is free and open source; tokens and sandbox time bill to your own Nebius account.

# 1. credentials (add to your shell profile)
export NEBIUS_API_KEY="…"          # Token Factory API key
export NEBIUS_PROJECT_ID="…"       # project with Sandboxes enabled
export TAVILY_API_KEY="…"          # optional, for feature-researcher

# 2. inside Claude Code
/plugin marketplace add Sppdd/900
/plugin install sandcoder@sandcoder
claude mcp add sandcoder \
  -e NEBIUS_API_KEY="$NEBIUS_API_KEY" -e NEBIUS_PROJECT_ID="$NEBIUS_PROJECT_ID" \
  -- uvx --from git+https://github.com/Sppdd/900 sandcoder-mcp
# ~/.codex/config.toml
[mcp_servers.sandcoder]
command = "uvx"
args = ["--from", "git+https://github.com/Sppdd/900", "sandcoder-mcp"]
env = { NEBIUS_API_KEY = "…", NEBIUS_PROJECT_ID = "…" }
// .cursor/mcp.json
{
  "mcpServers": {
    "sandcoder": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/Sppdd/900", "sandcoder-mcp"],
      "env": { "NEBIUS_API_KEY": "…", "NEBIUS_PROJECT_ID": "…" }
    }
  }
}
alias sandcoder="uvx --from git+https://github.com/Sppdd/900 sandcoder"

sandcoder panel "pre-merge check" -w . -s security-auditor,test-writer -t "python -m pytest -q"

# bring your own skills (reviewed, pinned by commit + content hash)
sandcoder skills add github:mattpocock/skills/skills/engineering --only tdd,diagnosing-bugs
sandcoder skills add ~/.claude/skills/my-skill
sandcoder skills                     # list specialists + library skills
sandcoder panel "fix the bug test-first" -s tdd   # any library skill can run as a specialist

Then just ask

  1. "Check this repo before I open the PR." Your agent calls panel_run with security-auditor and test-writer and keeps working.
  2. A few minutes later it calls panel_results and summarizes blocking findings first, each with file, line and proving command.
  3. It shows each patch as a diff with its risk rating from panel_patch, and applies it only if you say so.
  4. Shortcuts: /panel, or the MCP prompts panel_premerge, panel_repro and panel_research.

Build your own sandbox, filled with skills

A sandbox profile (sandbox.toml) is a reusable sandbox: base image, tools baked into a cached image, project setup, the specialists to run, and a skill library. Library skills are standard SKILL.md skills, such as ones from mattpocock/skills, your own, or ones autoharness learned. They are mounted in every sandbox, and agents load one when it fits. Any library skill can also run as a specialist on its own.

MCP reference

    
A deliberately small surface. Runs are asynchronous, and everything a specialist returns is untrusted data.

    

      

        
ToolWhat it does

        
          
panel_runStarts specialists on a copy of the project. Args: task, skills, path, test, setup, image, skill_tasks, library, profile. Uses the project's sandbox.toml automatically. Returns a run_id immediately.

          
panel_resultsVerdicts, findings, test status, patch summaries, guard denials and token use. wait_seconds (max 120) blocks until done.

          
panel_patchOne specialist's unified diff with its risk level and reasons. Review it before applying.

          
panel_cancelCancels a running panel.

          
panel_runsRecent runs with status and task.

          
skills_listSpecialists and library skills (built-in, installed, project), with version hashes. Installing skills is deliberately CLI-only: sandcoder skills add.
